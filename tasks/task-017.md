## 할 것
- 승인된 스택에서 대표 그래프 샘플을 사용해 3D 렌더링·검색/필터·선택·카메라 조작 가능성을 검증한다.
- 대상 Windows 기기·샘플 노드/관계 수·프레임/응답 측정 방식을 기록하고, 측정 결과에 근거해 표시 상한과 성능 합격 기준을 결정한다.
- 2D·목록 대체 경로, 키보드 탐색, 동작 감소, WebGL 미지원·오류 시 동작을 점검한다.
- 확정된 상한·성능 기준·설계 선택을 PRD Q7·Q13, S-03, A-05에 일치시킨다.
- 초기 프로토타입은 `spikes/brain-graph/`에서 샘플 데이터만 사용해 검증하며, 제품 앱 통합은 스파이크 완료 및 W0 나머지 게이트 후 진행한다.

## 하지 않을 것
- 제품 앱에 그래프 기능 구현
- 실제 사용자 자료를 스파이크에 복사
- 측정 전 임의의 수치나 성능 달성을 완료로 기록

## 현재 검증
- `spikes/brain-graph/`에서 샘플 자료 18개와 중앙 허브를 포함한 19개 노드·관계 28개의 Three.js 그래프를 구현했다.
- `npm run build` 성공. Three.js 번들은 minify 후 574.93 kB( gzip 144.38 kB)이며 Vite의 500 kB 청크 경고가 남아 있다.
- 브라우저 스모크 테스트에서 Raycaster 선택, 2D·목록 전환, 검색·필터, 키보드 포커스 이동, `prefers-reduced-motion` 전환을 확인했다.
- WebGL 컨텍스트 생성 차단 테스트에서 2D 대체 화면과 안내 상태를 확인했다.
- (2026-11-20) 시드 고정 합성 샘플(100~50,000노드, 관계 1.5배)과 `?bench=N` 벤치 모드로 Ryzen 5 5600X·RTX 3060에서 측정했다(`spikes/brain-graph/BENCHMARK.md`, `bench-results/`). 현 프로토타입 구조는 500노드부터 60 fps 미달, 단일 버퍼 렌더러는 50,000노드까지 프레임 p95 16.8 ms.
- 사용자 결정(2026-11-20): 단일 버퍼 렌더링(three 유지), 상한 노드 2,000·관계 3,000, 합격 기준 확정. 저사양·Electron 창은 task-016 알파에서 재측정.
- `WEBGL_lose_context`로 컨텍스트 손실을 일으켜 2D 자동 전환·3D 버튼 비활성·안내 문구를 headless Chrome에서 확인했다.
