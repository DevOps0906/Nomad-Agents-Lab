# Nomad-Agents-Lab — SSR+ 개인 AI 업무 시스템 기획

**Status**: Planning  
**Created**: 2026-11-02  
**Mode**: Plan & design only

## 1. Project Overview

### 제품 정의

Windows 데스크톱에서 개인 지식, 재사용 가능한 AI 스킬, 예약 루틴, 외부 도구 연결 및 실행 결과를 한곳에서 관리하는 로컬 우선 개인 AI 업무 시스템이다. SSR+는 제품의 네 기능 영역인 **Skill, Second Brain, Routine, Extension**을 뜻한다. SSR+를 서버 사이드 렌더링 기술의 의미로 사용하지 않는다.

### 문제와 제품 원칙

개인 지식이 파일·메모·클라우드 서비스에 흩어지고, 반복 작업의 지침·실행 시점·외부 도구 권한이 분리되면 결과와 데이터 흐름을 추적하기 어렵다. 이 제품은 지식에서 스킬과 루틴으로 이어지는 흐름을 한 화면 체계 안에 모으되, 외부 전송이나 도구 실행을 사용자가 통제하도록 설계한다.

1. **Local-first**: 연결하지 않아도 로컬 자료, 메모, 스킬, 실행 기록을 사용할 수 있다.
2. **명시적 동의**: 클라우드 연결, MCP/API 요청, 자료 전송 및 루틴 실행은 기본 비활성화다. 범위와 목적을 사용자에게 보여 준 후 명시적으로 허용한다.
3. **출처와 상태의 가시성**: 자료 출처, 마지막 동기화, 실행 주체, 입력·출력, 실패 원인을 확인할 수 있다.
4. **단계적 자동화**: 처음에는 미리보기·승인 후 실행을 기본값으로 하고, 반복해서 신뢰가 확인된 루틴만 사용자가 별도로 자동 실행을 허용할 수 있다.
5. **정보 밀도와 차분함**: 데스크톱에서 탐색·검토·실행이 빠르고, 색과 움직임은 상태와 관계를 돕는 범위로 제한한다.

### 대상 사용자와 성공 결과

- **대상**: Windows PC에서 Claude 계열 도구 또는 다른 AI 도구로 개인 지식과 반복 작업을 다루며, 자료 이동·외부 연결을 직접 통제하고 싶은 개인 사용자.
- **주요 결과**: 자료를 연결해 찾고, 관련 지식을 살펴보고, 스킬이나 루틴으로 작업을 수행한 다음 결과·권한 사용·실패를 추적할 수 있다.
- **MVP 범위**: 전체 현황, Second Brain, Skills, Routines, Extensions/MCP, 에이전트 실행 기록, 설정·가져오기/내보내기의 7개 화면 영역을 기획하고 설계한다.

### 포함하지 않는 것

- 이 작업에서의 애플리케이션 구현, 동작하는 UI 프로토타입, 서비스 배포 또는 실제 외부 연결
- `nomad-agent-os` 저장소 변경
- 자동 승인 없이 사용자 의도를 추측해 파일을 변경하거나 임의로 외부에 자료를 전송하는 에이전트
- MVP에서의 모바일 우선 앱, 다중 사용자·조직 관리, 공개 마켓플레이스, 클라우드 동기화 기본 제공
- 모든 외부 도구와 모든 파일 형식의 완전한 호환성 보장

## 3. Information Architecture & User Flows

### 전역 구조

좌측 고정 내비게이션은 **대시보드 → Second Brain → Skills → Routines → Extensions → 실행 기록 → 설정** 순서다. 상단에는 전역 검색, 연결/인덱싱 상태, 알림 및 사용자 메뉴를 둔다. 선택한 자료·스킬·루틴의 세부 내용은 기본적으로 같은 화면의 우측 상세 패널에서 확인해 문맥 전환을 줄인다.

### 핵심 사용자 흐름

1. **처음 시작 및 신뢰 형성**: 대시보드 → 로컬 데이터 위치 선택 → 폴더를 명시적으로 지정 → 지원 파일 형식·인덱싱 대상 미리보기 → 로컬 인덱싱 승인 → 완료·제외 항목 확인. 원격 소스는 별도 연결 전까지 표시만 하거나 비활성 상태로 둔다.
2. **자료 찾기 및 이해**: 전역 검색 또는 Second Brain 검색 → 결과에서 출처·수정 시점·연결 관계 확인 → 노드 선택 → 미리보기에서 원문 열기/관련 항목 확인. 검색 질의나 원문을 외부로 전송해야 할 때는 전송 전 그 사실과 대상을 표시하고 별도 승인을 받는다.
3. **스킬 실행**: Skills 목록 → 스킬 상세에서 목적·필수 입력·접근 자료·사용 도구 확인 → 입력 검토 → 실행 전 변경/전송 예상 범위와 권한 확인 → 승인 후 실행 → 결과와 생성된 기록·자료 연결 확인.
4. **루틴 예약 및 관리**: Routines → 루틴·시간대 선택 → 사용할 스킬·자료·외부 연결 검토 → 첫 설정은 승인 필요 모드로 저장 → 실행 예정과 다음 동작 확인 → 결과 검토. 자동 실행은 사용자가 해당 루틴에서 범위·시간·오류 시 동작을 따로 설정한 경우에만 가능하며 언제든 중지할 수 있다.
5. **외부 연결**: Extensions → 연결 유형과 제공자 검토 → 권한/범위 및 데이터가 전송되는 곳 확인 → 사용자 주도 연결 승인 → 연결 테스트 → 허용 목록 및 연결 상태 확인/해제. 읽기 전용 권한과 쓰기/실행 권한은 분리한다.
6. **실패 조사와 복구**: 실행 기록에서 실패 항목 선택 → 단계별 상태, 오류 요약, 사용한 도구·자료 확인 → 재시도 전 동일 입력/외부 요청 여부 검토 → 사용자가 재시도 또는 취소 선택. 비밀 토큰과 민감한 원문은 기본적으로 기록에 노출하지 않는다.
7. **이동·백업**: 설정 → 내보낼 자료 유형·포함 범위·저장 위치 선택 → 민감 항목과 외부 전송 여부를 확인 → 승인 후 로컬 내보내기. 가져오기는 덮어쓸 항목과 충돌을 먼저 미리 보여 준다.

### 공통 상태와 피드백

연결하지 않음, 연결 필요, 동기화/인덱싱 중, 승인 대기, 실행 중, 성공, 부분 완료, 실패, 권한 거부 및 취소 상태를 문구·아이콘·색으로 함께 표현한다. 색만으로 구분하지 않는다. 모든 데이터/연결 관련 화면에는 연결 대상, 마지막 동기화, 실행 또는 동기화 중지 동작을 제공한다.

## 4. Technical Architecture & Stack Recommendation

### 권장안

| 계층 | 추천 | 역할 및 이유 |
|---|---|---|
| 데스크톱 셸 | Electron 안정 릴리스 | Windows 우선 배포와 Node 생태계를 활용해 로컬 파일·MCP/API 연결 등 데스크톱 통합을 단순화한다. 웹 UI와 로컬 서비스 간 경계는 IPC로 유지한다. |
| UI | React + TypeScript + Vite | 대시보드, 검색·상세 패널, 반복 가능한 화면 컴포넌트와 설계 시스템 구현에 적합하다. SSR은 제품 요구가 아니므로 브라우저 UI 번들 기반으로 설계한다. |
| 컴포넌트 | Fluent UI v9 | 데스크톱 생산성 도구의 일관된 폼·메뉴·대화상자·상태 표현을 제공한다. 그래프·문서 뷰어는 이를 보완하는 전용 시각화/뷰어 요소로 구성한다. |
| 로컬 데이터 | SQLite | 메타데이터, 앱 내 메모, 관계·실행 기록·설정의 트랜잭션 저장. 대용량 원본 파일은 앱 DB에 복제하기보다 사용자가 지정한 경로를 참조하는 구조를 우선한다. |
| 검색·인덱스 | SQLite FTS 기반 텍스트 검색부터 시작 | 로컬 검색을 외부 서비스 없이 제공하고 운영 요소를 줄인다. 규모나 의미 검색 품질 요구가 확인되면 별도 로컬 벡터 인덱스를 평가한다. |
| 파일 파서 | 제한된 형식별 로컬 파서 | Markdown·PDF 텍스트 추출 및 인덱싱. 원본 파일 변경이나 업로드 없이 읽기 전용으로 시작하고 손상/암호화 PDF 등의 제한을 명시한다. |
| 3D 그래프 | Three.js 계열의 React 통합을 기술 검증 후 선택 | 노드 탐색·회전·확대와 선택 피드백을 표현할 수 있다. 대규모 그래프에서 성능·키보드 대체 탐색·화면 읽기 지원을 프로토타입 아닌 별도 기술 검증 단계에서 판단한다. |
| 외부 연결 | 승인 기반 MCP/API 어댑터 | 서버/도구별 권한·허용 목록·연결 상태를 분리하고, 호출 전 데이터 전달 범위를 보여 준다. 지원 프로토콜과 서버별 안전성은 구현 전 검증한다. |
| 비밀값 저장 | Windows 자격 증명 관리자 또는 OS 보호 저장소 연계 | 토큰·자격 증명을 평문 설정 파일, DB, 로그, 프론트엔드 번들에 저장하지 않는다. 데스크톱 셸 경계와 운영체제 연동을 검증한다. |

### 데이터 흐름 및 보안 경계

`React renderer (권한 없는 UI)` → 제한된 IPC 명령 → `Electron main/local service` → (1) 읽기 전용 로컬 파일 어댑터 (2) SQLite (3) 기본 차단 상태의 외부 연결 어댑터. Renderer에 Node 전체 접근을 주지 않고, 명시적 IPC 계약·입력 검증·출처별 권한으로 경계를 둔다. 인터넷 접근이나 외부 MCP/API 호출은 기본 거부하며, 연결별로 사용자가 허용한 작업만 수행한다.

### 대안과 절충

- **Tauri 2 + React**: 번들·메모리 사용량을 줄일 가능성이 있으나, Rust 학습과 데스크톱 플러그인·Node MCP 도구 통합 경계를 별도로 검증해야 한다. 배포 크기나 리소스 비용이 핵심 제약으로 확인되면 재평가한다.
- **웹 앱/PWA**: 배포가 간편하지만 OS 파일 접근·백그라운드 예약·자격 증명 보호·로컬 실행 경계 요구와 맞지 않아 MVP 우선안으로 추천하지 않는다.
- **클라우드 DB/동기화 우선**: 다기기 편의는 얻지만 기본 비활성화된 외부 전송이라는 요구와 충돌한다. MVP에서는 로컬 데이터 저장을 기준으로 하고 동기화는 별도 동의·위협 모델·충돌 해결 설계가 있을 때만 후속 검토한다.
- **3D 그래프 라이브러리**: 특정 라이브러리를 기획만으로 확정하지 않는다. 데이터 규모, 접근성, 렌더링 성능과 유지보수성을 기술 검증해 선택한다.

## 5. Data, Privacy & Operational Model

### 데이터 분류와 보존

| 데이터 | 기본 위치·정책 | 외부 전송 |
|---|---|---|
| 원본 Markdown/PDF | 사용자 지정 폴더에 유지. 인덱싱은 읽기 전용을 기본값으로 함 | 기본 금지. 외부 AI/연결에 일부를 전달할 때 자료·수신자·목적을 미리 표시하고 매 작업마다 승인 |
| 앱 메모·메타데이터·관계 | 로컬 SQLite | 사용자가 내보내거나 특정 연결로 보낼 때만 승인 |
| 검색 인덱스 | 로컬 SQLite FTS로 시작 | 원격 인덱싱은 MVP 기본 범위 아님 |
| 자격 증명 | OS 보호 저장소에 위임 | UI/로그/내보내기에 포함하지 않음 |
| 실행 이력 | 로컬 DB, 민감 입력/출력은 요약 또는 마스킹 옵션 | 외부 전송 기본 금지 |
| 샘플 데이터 | 명시적 샘플 세트로 분리하고 실제 사용자 자료와 표시·저장 경계를 구분 | 외부 전송 금지 |

### 동의, 권한, 복구

- 로컬 폴더 선택은 파일 선택 후에도 대상 경로와 읽을 파일 형식을 다시 표시한다. 광범위한 드라이브 전체 접근을 기본값으로 두지 않는다.
- Google Drive 연결은 사용자가 선택한 계정/폴더와 최소 권한 범위를 설명한다. 동기화·해제·로컬 캐시 삭제의 결과를 분명히 보여 준다.
- MCP/API 도구는 읽기·쓰기·실행 권한을 구별한다. 호출 직전 대상·입력 자료·예상 효과를 검토할 수 있게 한다.
- 루틴은 실행 모드(매번 승인/승인된 범위에서 자동), 일정, 시간대, 실패 시 중지/재시도 조건을 사용자 설정으로 보관한다. 새 도구/권한 요청이나 입력 범위 확대는 자동 승인을 무효화한다.
- 삭제·가져오기·내보내기는 되돌릴 수 있는 범위와 덮어쓰기 위험을 미리 알려 준다. 백업 암호화 및 복구 절차는 구현 전 요구사항으로 검증한다.
- 로그에는 비밀값, 불필요한 원문, 인증 헤더를 기록하지 않는다. 보존 기간과 이력 삭제를 설정에서 제어하도록 설계한다.

## 6. Design System & UI

**Component Library**: Fluent UI v9  
**언어**: 한국어 우선. 날짜·숫자·오류 문구는 일관된 현지화 규칙을 사용한다.  
**시각 방향**: 차분한 중성 바탕, 높은 텍스트 대비, 절제된 강조색. 지식 노드는 주제별 색상으로 구분하되 색상 외 라벨/형태 단서를 함께 쓴다. 레이아웃은 참고 영상의 구체 화면을 복제하지 않고 제품의 정보 구조에 맞게 새로 구성한다.  
**레이아웃**: 데스크톱에서 고정 좌측 내비게이션 + 페이지 본문 + 맥락형 우측 상세 패널. 작은 창에서는 패널을 접거나 오버레이로 바꾼다.  
**접근성**: 키보드 경로, 명시적인 포커스 표시, 충분한 대비, 의미 있는 제목/레이블을 제공한다. 3D 뷰에는 2D 목록·검색·관계 패널의 동등한 대체 경로를 둔다. `prefers-reduced-motion`을 존중하고 애니메이션을 정지할 수 있게 한다.

### 공통 탐색·시각화 동작

- 전역 검색은 제목·본문·태그·출처를 필터링하며, 로컬 전용 검색인지 외부 검색인지 항상 명시한다.
- 3D 그래프는 포인터 드래그로 회전, 휠/트랙패드로 줌, 선택 노드 고정, 관계 중심 재배치, 초기 시점 복귀를 제공한다. 사용자가 회전 애니메이션을 멈추면 시점이 계속 변하지 않는다.
- 키보드 사용자는 검색 결과 목록에서 노드를 이동·선택하고, 선택한 항목의 연결 노드를 관계 목록으로 탐색할 수 있다. 3D 캔버스만으로 작업이 불가능한 흐름을 만들지 않는다.
- 노드 선택은 윤곽선·라벨·상세 패널로 함께 나타낸다. 그래프가 크거나 연결이 많을 때 모든 선을 한 번에 그리지 않고 현재 선택 및 필터와 관련된 부분을 강조한다.
- 문서 미리보기는 제목·유형·경로/출처·마지막 수정 정보·인덱싱 상태를 표시한다. 원본 열기 동작은 사용자의 로컬 파일 열기임을 명확히 한다.

### 화면별 설계

#### 1) 전체 현황 대시보드

- **목적**: 시스템 상태와 오늘 검토할 일을 한눈에 파악한다.
- **구성**: 상단의 인덱싱·연결 건강 상태, `승인 대기`/`실행 중`/`실패` 요약, 다음 루틴 일정, 최근 실행, 최근 수정 지식, 빠른 작업(폴더 추가·메모·스킬 탐색). 위젯은 사용자 자료와 연결 상태를 혼동하지 않게 라벨링한다.
- **상호작용**: 상태 카드를 누르면 원인/대상 목록으로 이동, 승인 대기 카드는 검토 화면으로 연결한다. 연결이 없을 때는 로컬 사용 시작을 안내하고 외부 계정 연결을 강요하지 않는다.
- **빈 상태**: 샘플 데이터 보기와 사용자 폴더 선택을 별도 선택지로 제시한다. 샘플은 실제 인덱스와 시각적으로 구분한다.

#### 2) Second Brain — 3D 그래프·검색·미리보기

- **목적**: 지식 항목과 관계를 탐색하고, 선택한 문서의 맥락을 확인한다.
- **구성**: 상단 검색·필터(주제/자료 형식/출처/기간), 중앙 그래프, 우측 문서 미리보기 및 관련 노드 목록. 선택 노드는 강조하고 경로/출처를 제공한다. 노드 범례와 그래프 표시 수를 표시한다.
- **상호작용**: 회전/줌/초기화/일시정지, 검색 결과로 이동, 선택 노드 고정, 관계 깊이·주제 필터. 노드를 누르면 문서 미리보기와 인접 관계를 갱신한다. 노드 연결 관계는 앱이 추출/생성한 관계와 사용자가 직접 만든 관계를 구분한다.
- **접근성·성능 대안**: 그래프 캔버스 외에 검색 결과 리스트 및 키보드 가능한 관계 목록을 제공한다. 저사양·동작 감소 설정에서는 2D/정지 레이아웃을 기본 대안으로 제공한다. 큰 그래프는 뷰포트·검색·필터 결과 중심으로 제한한다.

#### 3) Skills — 목록·상세·실행

- **목적**: 재사용할 작업 지침을 발견하고 통제된 입력으로 실행한다.
- **구성**: 검색·카테고리·활성 상태 필터가 있는 목록, 상세 패널의 설명·필수 입력·참조 지식·도구 권한·최근 실행·버전/수정 정보.
- **상호작용**: 실행 전에 입력과 사용 가능한 자료를 검토한다. 도구 호출/자료 전송이 있으면 승인 화면에 수신자·자료 범위·예상 효과를 노출한다. 결과는 실행 기록과 관련 자료로 연결한다. MVP에서 스킬의 안전한 작성·편집 형식과 실행 샌드박스는 구현 설계 단계에서 별도 검증한다.

#### 4) Routines — 일정·이력

- **목적**: 반복 작업의 일정, 승인 수준 및 결과를 이해하고 중지할 수 있다.
- **구성**: 다음 예정 순서와 캘린더/목록 전환, 루틴 카드의 스킬·주기·다음 실행·승인 모드, 세부 패널의 시간대·입력 범위·허용 연결·실패 정책·실행 이력.
- **상호작용**: 생성/수정·일시 중지·재개·수동 실행. 신규 루틴 기본값은 매번 승인이다. 자동 실행 선택 시 권한 요약과 사용자가 감수할 결과를 추가 확인하며 권한 범위가 변경되면 재승인을 요구한다.

#### 5) Extensions / MCP — 연결 관리

- **목적**: 외부 도구 연결과 데이터 경계를 명확히 관리한다.
- **구성**: 연결별 제공자·프로토콜·상태·허용 도구·마지막 사용 시각, 세부 권한 목록, 접속/테스트/해제 제어, 승인 내역. 등록되지 않은 서버는 실행하지 않는다.
- **상호작용**: 추가 시 서버/도구 설명과 권한 차이를 확인하고, 연결별 승인. 읽기와 변경/실행 권한을 별도 토글·확인으로 다룬다. 호출마다 실제로 전송될 자료를 검토할 수 있어야 한다. 해제 시 토큰과 캐시 처리 결과를 안내한다.

#### 6) 에이전트 실행 기록

- **목적**: 작업 진행, 승인, 외부 도구 사용 및 결과를 사후 검토한다.
- **구성**: 시간순 실행 목록, 상태·스킬·루틴·도구·기간 필터, 상세 타임라인(입력 요약, 승인 이벤트, 도구 사용, 결과, 오류). 민감 텍스트는 기본 마스킹한다.
- **상호작용**: 승인/취소, 실행 중지(가능한 작업에 한함), 안전한 재시도, 결과/로그 정리. 재시도는 새 실행으로 기록하고 원 실행을 덮어쓰지 않는다.

#### 7) 설정·가져오기/내보내기

- **목적**: 로컬 데이터 위치, 연결, 접근성, 개인정보 및 이동성을 사용자 통제 아래 둔다.
- **구성**: 데이터 저장 경로/인덱싱 상태, 지정 로컬 폴더, Google Drive 연결(기본 미연결), 샘플 데이터, MCP/API 권한 바로가기, 언어·테마·동작 감소, 백업/가져오기/내보내기, 개인정보·로그 보존.
- **상호작용**: 폴더별 제외·재인덱싱·연결 해제. 내보내기 전 포함 항목, 민감 데이터, 저장 대상/외부 전송 여부를 미리 본다. 가져오기는 충돌 및 덮어쓰기 목록을 보여 준 뒤 승인받는다.

## 7. Delivery Phases & Acceptance Criteria

> 이 절은 향후 구현을 위한 권고 단계다. 현재 작업에서 구현을 수행하거나 프로토타입을 생성하는 범위가 아니다.

### 권고 단계

1. **제품 경계·위협 모델**: 파일/클라우드/MCP 데이터 흐름, 승인 원칙, 파일 접근 정책, 로그·백업·삭제 요구사항을 확정한다.
2. **로컬 기반**: 데스크톱 셸, 접근 제한된 IPC, SQLite, 로컬 폴더 읽기, Markdown/PDF 파싱, 검색·인덱싱 상태와 실패 복구를 설계/검증한다.
3. **핵심 탐색·스킬**: 대시보드, 2D 검색 경로, Second Brain 관계 모델, 3D 뷰 선택/대체 탐색, 스킬 입력·실행 기록을 구현한다.
4. **루틴·기록**: 사용자 승인 기본값, 시간대·중지 동작, 실패·재시도 기록을 검증한다. OS 스케줄링 제약과 앱 종료 상태를 결정한다.
5. **외부 연결·이동성**: 먼저 하나의 제한된 연결을 선택해 권한 최소화·매 호출 확인·해제·토큰 보호를 검증한 다음 확장한다. Google Drive와 MCP/API를 동시에 무제한으로 열지 않는다.
6. **품질·Windows 배포 검증**: 접근성, 그래프 성능, 데이터 이전·백업/복구, 업데이트·서명·설치/제거, 데이터 삭제를 점검한다.

### 수용 기준

- 각 MVP 영역에 요구한 목록/상세/빈 상태/로딩/오류 상태와 주요 상호작용이 화면 설계에서 정의되어 있다.
- 기본 설치 또는 첫 실행만으로 원격 연결·업로드·동기화가 시작되지 않는다. 외부 전송 전 사용자에게 대상·자료 범위·목적을 보여 주고 승인받는다.
- 로컬 소스는 사용자가 지정한 범위 안에서만 접근하며, 인덱싱과 미리보기에서 원본을 변경하지 않는 정책을 검증한다.
- 3D 조작에 마우스·키보드 대체 경로가 있고, 선택·필터·회전 정지·초기화 및 동작 감소 동작이 정의되어 있다.
- 스킬/루틴 실행 전 승인 기준, 권한 변경 시 재승인, 취소/중지, 실패와 재시도 기록이 정의되어 있다.
- 로그와 설정 내보내기에서 자격 증명·인증 헤더가 노출되지 않도록 설계되어 있다.
- 가져오기/내보내기에서 충돌·민감 정보·저장 위치·복구 경로가 사용자에게 명시된다.
- Windows 배포, 파일 접근, OS 자격 증명 저장, 예약 실행 및 PDF 파싱의 기술 제약은 구현 단계의 검증 항목으로 추적된다.

## 8. Risks, Decisions & Open Questions

| 위험/미결정 | 영향 | 대응·결정 시점 |
|---|---|---|
| Electron 프로세스 경계 및 외부 콘텐츠 취약점 | 로컬 파일/자격 증명 노출 | 구현 전 threat model과 보안 검토. renderer 권한 최소화, IPC 명령 allowlist, CSP, 의존성·업데이트 정책 검증 |
| MCP 서버/도구의 동작과 권한 범위 차이 | 의도치 않은 자료 외부 전송 또는 변경 | 서버별 기능/권한 검증, 기본 거부, 사용자 허용 목록, 작업 전 승인, 연결 해제·감사 기록 |
| 원격 연결과 로컬 우선성 간 상충 | 사용자 데이터의 위치·복제·삭제 불명확 | 소스별 동기화/캐시 정책, 삭제·해제 시 처리, 최소 권한을 제공자별로 확인 |
| PDF 파싱 품질·암호화/스캔 문서 | 검색 누락, OCR 범위 확장 가능성 | MVP에서 텍스트 추출 지원 범위를 정의. OCR은 별도 개인정보·성능·언어 검토 전까지 기본 가정하지 않음 |
| 대규모 그래프 성능·시각적 혼잡 | 탐색 저하 및 접근성 장벽 | 데이터 규모별 성능 검증, 검색/필터 중심, 2D 목록 대체 제공. 3D 라이브러리는 검증 후 확정 |
| 예약 작업과 앱 종료/절전 상태 | 루틴 미실행 또는 중복 실행 | OS별 예약 보장 범위, 재시작 복구, 시간대·재시도·중복 방지 정책을 설계 단계에서 결정 |
| 로컬 데이터 손상·암호화/백업 기준 | 데이터 복구 불가 또는 민감도 확대 | 백업·복구·내보내기 위협 모델과 키 관리 정책을 기술 검증 후 확정 |

**현재 결정**: Windows 우선, 로컬 우선, 한국어 데스크톱 UI, Electron + React/TypeScript 후보 추천, SQLite 기반 로컬 저장 후보, 외부 연결 기본 비활성화.  
**구현 전 재확인**: 스킬 파일 형식과 실행기, 실제 AI 제공자, 로컬 모델 지원 여부, 루틴이 앱 종료 중에도 실행되어야 하는지, Google Drive 범위, MCP/API 지원 목록, 데이터 암호화/백업 정책, 예상 자료 규모와 그래프 크기, Windows 최소 지원 버전.
