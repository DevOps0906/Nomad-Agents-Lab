# SSR+ 플랫폼 개요
작성일 2026-11-20

> 이 문서는 저장소의 기획 문서를 모아 "이 플랫폼이 무엇인가"를 비개발자도 읽을 수 있게 정리한 설명서다. 새 결정은 담지 않았고, 문서에 없는 내용은 `미확인`으로 표시했다. 문서끼리 다르면 최신 결정(ADR·2026-11-20 결정)을 따르고 차이를 해당 장에 한 줄로 적었다.

---

## 1. 한 줄 정의와 핵심 가치

**SSR+는 Claude Code를 쓰는 Windows 개인 사용자를 위한 "로컬 우선 데스크톱 앱"이다.** 내 컴퓨터의 노트(Markdown·PDF)를 검색하고 관계 그래프로 살펴보며, 내가 승인한 범위 안에서 AI 스킬을 실행하고, 그 기록을 한곳에서 확인한다.

| 항목 | 내용 |
|---|---|
| 이름의 뜻 | SSR+ = **S**kill · **S**econd Brain · **R**outine · **E**xtension(네 기능 영역). 웹 기술인 "서버 사이드 렌더링"과 무관하다 |
| 핵심 가치 (1개) | "AI가 무엇을 읽고 무엇을 했는지 보이는 실행" |
| 제품 형태 | 설치형 Windows 데스크톱 앱. 서버·회원가입·로그인 없음 |
| AI 엔진 | 사용자 PC에 이미 설치·로그인된 **Claude Code**(명령줄 도구)를 앱이 대신 실행한다. 앱이 AI 서비스에 직접 요청하거나 API 키를 저장하지 않는다 |
| "로컬 우선"의 뜻 | 자료·색인·기록이 **기본적으로 내 PC에 저장된다**는 뜻이다. "오프라인"이나 "외부 전송 없음"이 아니다 |

중요한 한계: Claude Code가 실행되면 설정된 원격 AI 서비스가 승인한 폴더의 문서 내용을 처리할 수 있다. 그래서 앱은 **매 실행 전에** 이를 알리고 동의를 받는다(7장).

출처: `docs/01_PRD.md#1`, `docs/adr/0001-ai-engine-claude-code-cli.md`

## 2. 왜 만드나

### 2.1 풀려는 문제

Windows에서 Claude Code로 개인 작업을 하는 사람은 지식(로컬 노트·PDF), 스킬(`SKILL.md`), 실행 결과가 여기저기 흩어져 있다. 관련 자료를 찾고 스킬을 돌린 뒤 "AI가 무엇을 읽고 무엇을 했는지"를 한곳에서 확인하기 어렵다.

### 2.2 대상 사용자

| 구분 | 내용 |
|---|---|
| 1순위 | Claude Code를 설치·로그인해 쓰고, 로컬 폴더에 Markdown 노트와 스킬을 쌓아 둔 Windows 개인 사용자 |
| 첫 사용자 | 저장소 소유자 본인(개인 알파) |
| 지금 하는 방식 | 터미널·탐색기·노트 앱을 오가며 작업 |

### 2.3 린 가설과 통과 기준 (P1~P5)

가설: "위 고객이 로컬 지식 탐색 + 승인 범위가 보이는 스킬 실행 + 실행 기록을 한 앱에서 쓰면, 오가는 방식보다 **주 3일 이상** 쓸 것이다." 아래 숫자는 모두 **가설**이며 근거가 더 필요하다.

| # | 기준 | 목표(가설) | 측정 방법 | 판정 시점 |
|---|---|---|---|---|
| P1 | 본인 7일 중 앱 사용일 | 3일 이상 | 앱 사용·실행 기록의 날짜 | 알파 후 |
| P2 | 7일간 스킬 실행 | 10회 이상, 성공률 70% 이상 | 실행 상태 집계(취소는 제외) | 알파 후 |
| P3 | 첫 실행 → 첫 검색 결과 | 10분 이내 | 온보딩 시작~첫 검색 시각 | 알파 후 |
| P4 | 인터뷰 5명 중 "지금 방식보다 낫다" | 3명 이상 | 인터뷰 기록 | 외부 사용자 확대 전 |
| P5 | 승인 범위 밖 파일 접근 | 0건 | 실행 이벤트의 경로·도구 vs 승인 범위 | 알파 후 |

- 판정 규칙: P5 실패 → 보안 수정 전까지 보류 / P1·P2 미달 → 가설 수정. P4는 외부 확대 판단에만 쓰며 본인 알파 개발의 선행 조건이 아니다.
- 결과: **개발 착수 승인(2026-11-03)**. 개인 알파를 먼저 만든다.

출처: `docs/00_LEAN.md#문제·고객·가설·통과 기준·결과`

## 3. SSR+ 네 영역: 초기 비전과 현재 범위

초기 비전은 Copilot이 2026-11-02에 만든 기획(`.azure/project-plan.md`, 읽기 전용 이력)이다. 이후 사용자가 2026-11-03 **균형 MVP(ADR-0006)** 로 범위를 줄였다. "한 번에 7개 영역을 만들기엔 넓다"는 이유다.

| 영역 | 쉬운 설명 | 초기 비전 | 현재 범위 |
|---|---|---|---|
| **Skill** (스킬) | 반복 작업의 "작업 지침서". Claude의 표준 `SKILL.md` 폴더 그대로 사용 | 스킬 목록·상세·입력 확인·실행 승인·결과 연결 | **1차 포함**: 기존 `SKILL.md`를 찾아 목록·상세 확인 → 한 번에 하나를 승인해 실행. 스킬 편집기는 제외(앱에서는 "폴더 열기"만) |
| **Second Brain** (두 번째 뇌) | 내 노트를 문서=점, 연결=선으로 보여 주는 지식 지도 | 분야별 색 3D 그래프, 검색·필터, 노드 선택 시 미리보기, 앱 내 메모, Google Drive·MCP 자료 | **1차 포함**: 같은 관계 데이터를 3D·2D·목록으로 탐색(제한된 이웃만 표시). 관계는 링크·태그·폴더·직접 연결의 규칙 기반 추출. 앱 내 메모·Drive는 1차 범위 표에 없음 |
| **Routine** (루틴) | 스킬을 정해진 시간에 반복 실행 | 일정·실행 모드·최근 결과·일시 중지/재개 | **2차**: 앱이 켜져 있는 동안(트레이 상주) 예약. **3차**: 앱이 꺼져 있어도 Windows 작업 스케줄러로 실행 |
| **Extension** (확장) | 외부 도구·서비스 연결 | MCP/API 연결 목록·권한·테스트·해제, Google Drive 선택 연결 | **1차 미포함**(1차 실행은 MCP를 쓰지 않고 차단). MCP 연결 관리 **2차**, Google Drive **3차** |

- 초기 비전은 화면 7개 영역(대시보드·Second Brain·Skills·Routines·Extensions·실행 기록·설정/가져오기·내보내기)이었고, 현재 1차는 화면 8개(5장)다.
- 초기 비전에서 3D 그래프는 핵심 차별점이다. 2D만 1차에 넣고 3D를 미루는 안(ADR-0004)은 **대체**되어 3D가 1차에 들어갔다.
- 문서 간 차이: 스킬 편집기·임베딩 관계가 ADR-0006은 "2차", PRD 범위표는 "3차"로 적었다. 이 문서는 지시에 따라 ADR-0006을 따라 9장에서 2차로 쓰고 이 차이를 표시했다.

## 4. 사용 흐름: 7가지 시나리오

한 사용자가 처음 설치해 하루를 쓰는 이야기로 풀었다. 화면 번호(S-xx)는 5장 참조.

| # | 장면 | 이야기 | 성공 상태 | 화면 |
|---|---|---|---|---|
| 1 | 처음 켜서 쓸 준비 | 앱을 처음 켜면 "Claude Code가 설치·로그인돼 있나요?"를 먼저 확인한다. 노트 폴더를 고르고, 앱 데이터를 둘 위치를 정한다. 폴더가 없으면 샘플 자료로 시작할 수 있다 | Claude Code 확인, 데이터 위치, 첫 폴더(또는 샘플) 완료 | S-01 |
| 2 | 내 노트에서 자료 찾기 | 검색창에 단어를 넣고 태그·형식으로 좁힌다. 문서를 누르면 오른쪽에 미리보기가 뜨고, 원본은 절대 바뀌지 않는다 | 원본 변경 없이 찾기·미리보기 | S-03 |
| 3 | 지식 관계 살펴보기 | 그래프에서 점 하나를 고르면 "왜 연결됐는지"(링크·태그·폴더·직접 연결)와 관련 노드가 나온다. 3D가 불편하면 2D나 목록으로도 똑같이 할 수 있다 | 연결 이유와 이웃 확인 | S-03 |
| 4 | 스킬 실행 | 스킬을 고르면 어떤 AI 서비스가 처리하는지·입력·읽을 폴더·쓸 도구가 한 화면에 보인다. "이번 실행의 외부 AI 처리에 동의" 체크를 해야 실행 버튼이 켜진다. "이번만" 또는 "이 범위 기억"을 고른다 | 동의 후 실행 시작 | S-04, S-05 |
| 5 | 실행 중 추가 권한 판단 | 실행 중 Claude가 승인하지 않은 폴더나 도구를 쓰려 하면 앱에 요청이 뜬다. 허용·거부하거나 실행을 취소한다. 5분 동안 답이 없으면 거부로 처리된다 | 요청마다 사용자가 결정 | S-07 |
| 6 | 결과·이력 확인 | 실행 기록에서 상태(승인 대기·실행 중·성공·부분 완료·실패·취소)와 입출력 요약, 사용한 범위를 본다. 실패하면 "재시도"로 새 실행을 만든다(원래 기록은 보존) | 상태·범위 확인, 재시도 | S-06, S-07 |
| 7 | 현황·설정 관리 | 대시보드에서 색인 문서 수·승인 대기·실행 중·실패와 최근 실행을 한눈에 본다. 설정에서 연결 폴더를 해제하고 "기억한 허용"을 취소한다 | 상태 확인, 허용 해제 | S-02, S-08 |

화면 흐름(F): 첫 시작 `S-01→S-02→S-03` · 자료 찾기 `S-02→S-03` · 스킬 실행 `S-04→S-05→S-07→S-06` · 실패 조사 `S-02→S-06→S-07→S-05→S-07`.

## 5. 화면 구성 (S-01~S-08)

모든 화면 공통: 좌측 고정 내비게이션 + 본문 + 우측 상세 패널(태블릿 이하는 오버레이). 로그인 없음("로컬 사용자"). 상태는 문구·아이콘·색을 함께 쓴다.

| ID | 화면 | 유형 | 하는 일 | 다음 화면 |
|---|---|---|---|---|
| S-01 | 첫 실행 점검 | 마법사 | Claude Code 설치·로그인 확인 → 데이터 위치 → 첫 폴더 연결·색인 시작, 샘플 자료 시작 | S-02 |
| S-02 | 대시보드 | 대시보드 | 색인 문서 수·승인 대기·실행 중·실패, 최근 실행, 최근 수정 자료 | S-03, S-04, S-06, S-07, S-08 |
| S-03 | Second Brain | 상세 | 검색·필터, 3D·2D·목록 보기, 문서 미리보기, 관련 노드(연결 이유), 직접 연결 추가, 원본 열기 | S-04, S-02 |
| S-04 | 스킬 목록 | 목록 | 스킬 검색, 상세(목적·입력·참조 자료·도구), 폴더 열기, 실행 준비 | S-05, S-07 |
| S-05 | 스킬 실행 승인 | 폼 | 입력·접근 폴더·허용 도구 확인, 이번 실행 외부 AI 처리 동의, "이번만/기억" | S-07, S-04 |
| S-06 | 실행 기록 | 목록 | 상태·스킬·기간 필터로 과거 실행 찾기 | S-07 |
| S-07 | 실행 상세 | 상세 | 진행 상황, 권한 요청 허용·거부, 오류 요약, 취소, 재시도 | S-06, S-05, S-03 |
| S-08 | 설정 | 설정 | 데이터 위치·스킬 폴더·동작 감소·로그 보존, 연결 폴더 관리, 기억한 허용 해제 | S-02 |

- 그래프(S-03) 접근성: 3D를 쓰되 키보드만으로 같은 일을 할 수 있는 2D·목록 경로를 둔다. 동작 감소 설정이나 WebGL 오류 때는 자동으로 2D로 전환한다.
- 문서 간 차이: 초기 비전의 "루틴·확장(MCP)·가져오기/내보내기" 화면은 현재 1차 8개 화면에 없다(2차).

## 6. 차별점과 벤치마크 비교

### 6.1 경쟁 대안과 남는 불편

| 대안 | 지금 쓰는 방식 | 남는 불편 (SSR+가 다룰 점) | 근거 |
|---|---|---|---|
| Obsidian + Claude Code | 노트·그래프는 Obsidian, 터미널에서 `claude` 실행 | 스킬 목록·실행 승인 범위·실행 기록이 노트와 분리 | **미확인**(인터뷰로 확인) |
| Claude Code 단독(터미널) | 폴더에서 `claude`, 스킬은 `~/.claude/skills/` | 지식 탐색·그래프 없음, 실행 이력이 세션별로 흩어짐 | **미확인** |
| Claude Desktop + MCP 파일 서버 | 채팅 앱에 파일 접근 MCP 연결 | 로컬 색인·관계 탐색 없음, 접근 범위가 설정 파일에 숨음 | **미확인** |
| 노트 앱 내장 AI(Notion AI 등) | 클라우드 노트에서 AI 사용 | 로컬 우선 아님 | **미확인** |

### 6.2 화면 벤치마크 (Obsidian · Logseq · Raycast AI)

작성자 기억 기반이라 "반드시 있는 것"은 모두 **미확인**이며 공식 문서·실제 화면 확인이 필요하다.

| 제품 | 대응 화면 | 참고할 점 | 우리 결정 |
|---|---|---|---|
| Obsidian | 그래프 뷰(S-03) | 링크·태그 그래프, 필터, 그룹 색, 로컬 그래프(현재 문서 주변) | 부분 채택: 관계 종류 필터·분야 색은 반영, 로컬 그래프는 "관련 노드 목록"으로 대체 |
| Logseq | 페이지 + 참조 패널 | 역링크, "연결 안 된 참조" | 1차 미채택(결정적 추출 범위 밖), 2차 후보 |
| Raycast AI | AI 명령 실행(S-04·S-05) | 명령 검색, 실행 전 권한 확인 | 부분 채택: 검색·상세·실행 준비 구조 반영, 명령 팔레트는 2차 검토 |

### 6.3 차별점 요약 (문서 근거 기준)

| 차별점 | 설명 |
|---|---|
| 승인 범위가 보이는 실행 | 매 실행마다 처리 서비스·폴더·도구를 보여 주고 동의를 받음 |
| 설명 가능한 그래프 | 연결 이유를 항상 말할 수 있는 규칙 기반 관계(AI 추정 아님) |
| 기록 일원화 | 검색·스킬·실행 기록을 한 앱에서 확인 |

## 8. 기술 구성

### 8.1 쉬운 말로

앱은 세 겹으로 되어 있다.

1. **화면(Renderer)**: 사용자가 보는 부분. 파일이나 인터넷에 직접 닿지 못하게 막아 둔 "유리창"이다.
2. **본체(Main)**: 파일 읽기, 색인, 데이터베이스, Claude Code 실행을 맡는 부분. 화면이 요청하면 입력을 검증하고 허용된 요청만 처리한다.
3. **Claude Code**: 사용자의 PC에 이미 있는 AI 명령줄 도구. 본체가 "이 폴더·이 도구만"이라고 범위를 정해 실행시키고, 실행 중 추가 권한 요청은 앱의 승인 창으로 되돌려 보낸다. 이 연결은 앱 안의 **한 모듈**에만 모아, 도구 버전이 바뀌어도 한 곳만 고치면 된다.

흐름 한 줄: 사용자가 승인 → 본체가 범위를 확정 → Claude Code 실행(원격 AI 서비스와 통신 가능) → 진행 이벤트를 기록·화면에 표시.

### 8.2 구성 요소

| 요소 | 하는 일 |
|---|---|
| Renderer | 화면 S-01~S-08. 권한 없음 |
| Preload / IPC 라우터 | 허용된 17개 명령만 통과, 입력 검증 |
| 환경 점검 | Claude Code 설치·버전·로그인 확인 |
| 소스·색인 | 연결 폴더를 읽기 전용으로 순회, 텍스트·링크·태그 추출 |
| 검색·그래프 | 전문 검색, 노드·관계 조립, 미리보기 |
| 스킬 카탈로그 | `SKILL.md` 폴더 스캔 |
| 실행 관리자·Claude Code 어댑터·권한 브리지 | 동의 확인 → 범위 확정 → CLI 실행·이벤트 파싱 → 권한 질의 중계, 취소·재시도 |
| 저장소 | SQLite 단일 파일 |
