# 04 API — SSR+ (1차 MVP, Electron IPC)

> HTTP API 없음. 모든 호출은 Renderer → Main IPC다. 경계: [`02_ARCHITECTURE.md#2`](02_ARCHITECTURE.md) · 테이블: [`05_DATA_MODEL.md`](05_DATA_MODEL.md)

## 공통 규칙
- 메서드: `invoke`(요청·응답, Promise) / `subscribe`(Main → Renderer 이벤트). Preload가 아래 경로 이름만 허용한다.
- 모든 입력은 Main에서 스키마 검증한다. 경로 입력은 정규화 후 연결 폴더(`sources`) 안인지 검사한다.
- Renderer는 파일 경로를 보내지 않는다. 새 경로(A-02 폴더 추가·A-17 데이터 위치)는 Main이 연 OS 대화상자 결과만 쓴다.
- 권한 열 = Main이 그 명령을 처리할 때 쓰는 능력. Renderer 자체는 어떤 능력도 갖지 않는다.
- 모든 입력 스키마는 `.strict()`: 정의되지 않은 키(예: `path`)가 하나라도 있으면 `E_VALIDATION`. "입력 없음"은 `undefined` 또는 `{}`만 받는다.
- 경로 검사(데이터 위치·연결 폴더 공통, task-018): `realpath.native`로 실제 경로를 확정한 뒤 판정(junction·8.3 우회 차단). 거부: 드라이브 루트, UNC·`\\?\`(네트워크·장치 경로), `%WINDIR%`·Program Files 두 곳·`%PROGRAMDATA%`·`%USERPROFILE%\AppData` 전체·앱 userData(안쪽 포함), 홈 폴더 자체와 그 상위. 시스템 폴더는 환경 변수 값과 고정 기본값(`C:\Windows`·`C:\Program Files`·`C:\Program Files (x86)`·`C:\ProgramData`)을 함께 쓴다. 장치·UNC 형식(`\\?\`·`\\.\`·`//`·`\??\`)은 realpath가 일반 경로로 바꾸므로 원본 입력과 실제 경로 둘 다 검사한다. 연결 폴더는 홈 아래 `.ssh`·`.gnupg`·`.claude`·`.aws`·`.azure`·`.kube`·`.docker`·`.config`(자체·하위)도 거부(품는 상위 선택은 허용, 색인 제외는 task-019). 데이터 위치 경고: 동기화 폴더 `sync`, UNC `network`, 시스템 드라이브(`%SystemDrive%`) 밖 드라이브는 로컬 고정 디스크인지 확인하지 못하므로 `unverified`(매핑된 네트워크 드라이브 포함 가능). 데이터 위치와 연결 폴더, 연결 폴더끼리는 같음(대소문자 무시)·부모·자식 관계면 거부.
- 대화상자를 여는 처리(A-01b·A-02 add)는 하나의 잠금을 공유해 진행 중이면 `E_BUSY`.
- 공통 오류: `E_VALIDATION`(입력 형식) · `E_NOT_FOUND` · `E_OUT_OF_SCOPE`(연결 폴더·승인 범위 밖) · `E_CONSENT_REQUIRED`(이번 실행의 외부 처리 동의 누락) · `E_BUSY`(이미 진행 중) · `E_INTERNAL`(원문·스택은 Renderer에 보내지 않음).
