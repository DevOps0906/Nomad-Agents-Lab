# 00 린 검증 — SSR+

> SSR+ = Skill · Second Brain · Routine · Extension (서버 사이드 렌더링 아님). 근거: `.azure/project-plan.md#1`

| 항목 | 내용 |
|---|---|
| 문제 | Windows에서 Claude Code로 개인 작업을 하는 사용자는 지식(로컬 Markdown·PDF)·스킬(`SKILL.md`)·실행 결과가 흩어져 있어, 관련 자료를 찾고 스킬을 돌린 뒤 "AI가 무엇을 읽고 무엇을 했는지"를 한곳에서 확인하기 어렵다. |
| 고객 | 1순위: Claude Code를 이미 설치·로그인해 쓰고, 로컬 폴더에 Markdown 노트와 스킬을 쌓아 둔 Windows 개인 사용자(첫 사용자 = 저장소 소유자 본인) |
| 가설 | "위 고객은 로컬 지식 탐색 + 승인 범위가 보이는 스킬 실행 + 실행 기록을 한 데스크톱 앱에서 쓰면, 터미널·탐색기·노트 앱을 오가는 것보다 자주(주 3일 이상) 쓸 것이다." 지불 의사 금액은 **미확인**(검증 대상 아님, 1차는 사용 빈도만 검증) |
| 대안(경쟁) | 아래 대안 표 |
| 가장 싼 검증 | ① 본인 7일 사용 기록(도그푸딩, 1차 MVP 수직 슬라이스로) ② 같은 고객군 인터뷰 5명(현재 작업 방식·불편·대안 사용 이유) |
| 통과 기준 | 아래 통과 기준 표 (모든 숫자는 **가설**, 근거 필요) |
| 기한·비용 | 기한 **팀장 결정 필요**. 비용: 외부 비용 0원 목표(Claude Code 사용 요금은 사용자 기존 구독, 금액 **미확인**) |
| 결과 | **보류(검증 전)** — 검증 미실시. 1차 MVP는 검증 도구로만 만든다. |

## 대안(경쟁) 비교
| 대안 | 고객이 쓰는 방식 | 남는 불편 (SSR+가 다룰 점) | 근거 |
|---|---|---|---|
| Obsidian + Claude Code | Obsidian으로 노트·그래프, 터미널에서 `claude` 실행 | 스킬 목록·실행 승인 범위·실행 기록이 노트와 분리됨 | **미확인**(인터뷰로 확인) |
| Claude Code 단독(터미널) | 폴더에서 `claude` 실행, 스킬은 `~/.claude/skills/` | 지식 탐색·그래프 없음, 실행 이력은 세션 단위로 흩어짐 | **미확인** |
| Claude Desktop + MCP 파일 서버 | 채팅 앱에 파일 접근 MCP 연결 | 로컬 지식 색인·관계 탐색 없음, 접근 범위가 설정 파일에 숨음 | **미확인** |
| 노트 앱 내장 AI(Notion AI 등) | 클라우드 노트에서 AI 사용 | 로컬 우선 아님(자료가 클라우드에 있어야 함) | **미확인** |
