# ADR-0001 AI 실행 엔진: Claude Code CLI 연동

- 상태: 채택 (2026-11-03)
- 맥락: 원 기획(`.azure/project-plan.md` 8장)에서 "실제 AI 제공자"가 미결. 로컬 우선·외부 전송 기본 차단 원칙과 AI 호출이 충돌.

## 선택
앱은 AI API를 직접 호출하지 않는다. 사용자 PC에 설치·로그인된 **Claude Code CLI를 headless(`claude -p`)로 자식 프로세스 실행**하고 `--output-format stream-json`으로 진행·결과를 받는다. CLI는 구성된 AI 서비스와 통신할 수 있으므로 이 제품은 오프라인 앱이 아니다.
- 접근 범위는 실행마다 앱이 정한다: 작업 디렉터리 + `--add-dir`(승인된 폴더만), `--allowedTools`(승인된 도구만), `--mcp-config`(앱 권한 브리지 외 차단), `--max-turns`.
- 실행 중 추가 권한 요청은 `--permission-prompt-tool`로 앱 UI에 넘겨 사용자가 승인·거부한다(기술 검증 항목 T-01).
- 앱은 API 키를 저장하지 않는다. 인증은 Claude Code가 관리한다.
- 사용자가 매 실행 전에 원격 AI 처리에 동의해야 한다. 승인 화면은 Claude Code에 설정된 서비스, 승인 폴더, 전송될 수 있는 스킬·입력·문서 범위를 설명한다. 폴더 접근을 승인하면 모델이 그 안에서 실제로 읽을 파일의 정확한 목록은 실행 전에 확정되지 않을 수 있음을 알린다. 동의 기록은 실행 기록에 남기며, 기억한 폴더·도구 허용이 이 동의를 대신하지 않는다.

## 대안
| 대안 | 기각 이유 |
|---|---|
| Claude API 직접 | API 키 보관·별도 요금. 스킬·MCP 실행기를 다시 만들어야 함 |
| 로컬 모델 우선 | 사양·품질 부담. 2차 이후 재검토 |
| 공급자 추상화 | MVP 범위 확대 |

## 결과
- 앱 자체는 별도 AI API 요청을 보내지 않지만 Claude Code CLI가 구성된 원격 AI 서비스에 요청을 보낼 수 있다. 이를 로컬 저장과 혼동하지 않는다. 실행마다 처리 서비스와 승인 범위(폴더·도구·MCP)를 고지하고 동의를 받는다.
- 전제: 사용자는 Claude Code 설치·로그인 상태. 첫 실행 시 `claude --version`·로그인 상태를 점검한다.
- CLI 플래그·출력 형식이 바뀌면 깨진다 → 어댑터 1곳에 격리하고 지원 버전을 기록한다.
