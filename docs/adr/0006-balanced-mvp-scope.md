# ADR-0006 개발 가능한 균형 MVP 범위

- 상태: 채택 (2026-11-03, 사용자 승인)
- 맥락: 초기 비전의 7개 SSR+ 영역을 한 번에 구현하기에는 범위가 넓다. 반면 2D 그래프만 남기고 사용자가 요청한 Second Brain 3D를 후속으로 미루는 안은 핵심 차별점을 검증하지 못한다.

## 결정
첫 구현은 다음의 하나의 수직 흐름에 집중한다.

> 로컬 자료 연결·색인 → 검색·Second Brain 탐색 → 스킬 선택 → 외부 처리·접근 범위 승인 → 1회 실행 → 실행 기록 확인

| 1차 MVP 포함 | 구현 경계 |
|---|---|
| 첫 실행·로컬 자료 연결 | Windows 우선, Markdown·텍스트 추출 가능한 PDF, 샘플 자료 선택 |
| 검색·미리보기 | 색인된 자료만 탐색하고 원본은 읽기 전용 |
| Second Brain | 같은 관계 데이터를 3D 그래프와 2D·목록 대체 경로로 탐색. 한 번에 전체 지식 우주를 그리지 않고 검색·필터·중심 노드 기준의 제한된 이웃을 표시 |
| Skill 실행 | 기존 `SKILL.md`를 발견·선택하고 한 번에 하나를 명시 승인해 실행. 스킬 편집기는 제외 |
| 외부 처리 동의·실행 기록 | Claude Code가 설정된 AI 서비스에 요청을 보낼 수 있음을 매 실행 전에 고지·승인하고, 서비스 표시·폴더 범위·동의 시각을 기록 |
| 대시보드·최소 설정 | 자료·색인·최근 실행 상태와 승인 범위·동작 감소 설정 제공 |

### 명시적 동의와 로컬 우선
- 로컬 우선은 자료·색인·기록의 기본 저장 위치를 뜻하며, 오프라인 또는 외부 전송 없음의 의미가 아니다.
- Claude Code 실행은 기본 거부한다. 매 실행 전에 서비스, 승인 폴더, 스킬·입력·문서가 처리될 수 있음을 설명하고 사용자가 동의해야 한다.
- 폴더 범위를 승인해도 Claude가 읽을 정확한 파일 목록을 사전에 보장할 수 없다는 한계를 표시한다. 민감한 폴더는 승인하지 않도록 안내한다.
- 동의는 실행별이며 기억한 스킬·폴더 권한으로 대체하지 않는다. 앱은 동의 사실과 표시한 범위를 기록하되 문서 본문을 동의 로그에 복제하지 않는다.

### 3D·접근성 경계
- 3D 그래프는 MVP에 포함하되 검색·필터·중심 노드 주변을 탐색하는 제한된 그래프만 렌더링한다.
- 키보드만으로 동등한 핵심 작업을 할 수 있는 2D 그래프 및 목록·미리보기 경로를 제공한다. 동작 감소 설정에서는 자동 회전·강제 움직임을 끈다.
- 표시 상한과 목표 기기 성능은 W0 기술 스파이크(task-017)에서 실제 측정 후 확정한다. 결과를 UX·PRD·IPC 명세에 반영하기 전에는 3D 구현을 시작하지 않는다.

## 후속 범위
| 차수 | 기능 |
|---|---|
| 2차 | 루틴 예약, MCP 연결 관리, 가져오기·내보내기, 스킬 편집기, 임베딩 기반 관계 |
| 3차 | Google Drive, 앱 종료 중 루틴(Windows 작업 스케줄러) |

후속 기능은 현재 MVP나 첫 수직 흐름의 선행 조건이 아니다.

## 개발·검증 게이트
- 인터뷰 5명(P4)은 개인 알파의 개발·사용 선행 조건이 아니다. 첫 구현 후 본인 7일 알파(P1~P3·P5)를 수행하고, 외부 사용자 확대 전 인터뷰한다.
- W0에서 스택·CLI 권한·보안 설정·디자인 토큰·3D 성능 기준을 확인한다. 기술 검증 실패는 관련 기능의 범위 또는 구현 방법을 조정하는 근거이며, 완료된 것으로 간주하지 않는다.
- 이 ADR은 초기 비전인 [`.azure/project-plan.md`](../../.azure/project-plan.md)를 삭제·대체하지 않는다. 초기 비전은 이력으로 보존하고, 구현·검증 범위는 이 ADR과 현재 `docs/` 정본을 따른다.

## 결과
- [ADR-0004](0004-mvp-vertical-slice.md)의 2D 전용 MVP 제안은 대체한다.
- 초기 비전의 루틴·외부 연동·편집기·임베딩을 모두 한 번에 구현하지 않는다.
- 앱 구현 자체는 별도 작업 승인 전까지 시작하지 않는다. 다음 작업은 W0의 기술·설계 선행조건이다.
