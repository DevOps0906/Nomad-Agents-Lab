## 2. 샘플·측정 방식

- 샘플: `src/sample-graph.js` — 노드 수 N(허브 포함), 관계 round(1.5N), 시드 `20261120`(mulberry32) 고정. 같은 시드면 같은 그래프.
- 렌더러 2종
  - `prototype`: 현재 프로토타입(`index.html?bench=N`). 노드마다 Points 객체·HTML 라벨, 처음 4.5초 O(N²) force, 프레임마다 라벨 N개 투영.
  - `single-buffer`: 비교안(`bench.html?bench=N`). 노드 전체 Points 1개 + 관계 LineSegments 1개(draw call 2), 라벨은 선택+이웃 최대 24개, 레이아웃 사전 좌표(실시간 force 없음).
- 지표(`src/bench-harness.js`): 워밍업 5초 후 8초간
  - 프레임 간격: rAF 타임스탬프 차(평균·p95). 60 Hz에서 16.7 ms가 하한(vsync).
  - CPU 프레임: 애니메이션 콜백 안의 JS·렌더 제출 시간(p95).
  - 첫 렌더: 장면 생성 시작 → 첫 render 후 다음 rAF(데이터 생성·로드 제외).
  - 선택 응답: 노드 화면 좌표로 Raycaster 클릭 처리 → 다음 프레임 직후(20회 평균·p95). 적중 = 목표 노드가 선택된 비율.
  - 선택 상태 프레임: 마지막 선택(선택 노드·이웃 강조, single-buffer는 선택+이웃 라벨 투영)을 유지한 채 8초간 다시 측정.
- 실행: `npm run build` → `npx vite preview --host 127.0.0.1 --port 5182` → `node scripts/run-bench.mjs --base http://127.0.0.1:5182 --dpr 2 [--cpu-throttle 4]`.
  4173 포트는 이 PC에서 `EACCES`(예약 범위)라 5182를 썼다. 실행기는 OS가 고른 빈 디버깅 포트와 자신이 만든 임시 프로필의 엔드포인트에만 접속하고, 명령마다 30초 제한을 둔다.
- 저사양 근사: DevTools `Emulation.setCPUThrottlingRate 4`(CPU만 느리게, GPU는 그대로).

## 4. 결정 (확정 2026-11-20, 알파 재측정)

1. **렌더링 방식**: 현재 프로토타입 구조(노드별 객체·노드별 HTML 라벨·실시간 O(N²) force)는 500노드에서 p95 33 ms, 1,000노드에서 평균 34 ms로 60 fps를 못 지킨다. 제품 구현은 `single-buffer` 방식(Points/LineSegments 단일 버퍼, 선택·이웃만 라벨, 레이아웃은 렌더 루프 밖에서 계산)을 채택한다(사용자 결정). 라이브러리는 three 0.187.0 유지(새 의존성 없음).
2. **표시 상한: 노드 2,000 · 관계 3,000(부분 그래프 1회 응답, 파생 `tag`·`folder` 관계 포함, 3D·2D·목록 공통)**. 근거: single-buffer는 이 기기에서 50,000노드까지 vsync(16.8 ms)를 유지했고 CPU 4배 감속에서도 5,000노드 프레임 p95 16.8 ms였다. 그러나 저사양 GPU는 미측정이므로 측정 최대치 대비 여유를 두고, 사람이 읽을 수 있는 밀도(선택 적중 16~18/20)를 기준으로 2,000으로 정했다. 초과분은 잘림 배너와 검색·필터·중심 노드 깊이로 줄인다(선정 규칙은 `docs/04_API.md` A-05).
3. **합격 기준**(제품 구현, 상한 그래프, 대상 기기, DPR 실제값):
   - 회전 상태 프레임 간격 p95 ≤ 20 ms(60 Hz 기준)
   - 첫 렌더(데이터 수신 후) ≤ 500 ms
   - 선택 응답 p95 ≤ 50 ms, CPU 4배 감속에서 프레임 p95 ≤ 33 ms
   - 2D·목록 전환 ≤ 300 ms(현 DOM 방식 2,000노드 측정 166~249 ms)
   - 기준 미달 기기는 2D·목록 전환을 안내하고, WebGL 생성 실패·컨텍스트 손실은 2D로 자동 전환(S-03)
4. **미측정(task-016 알파에서 재측정)**: 저사양·내장 GPU 기기, 실제 Electron 45 창(headed·vsync 실측), 고주사율 모니터, 실시간 force 레이아웃의 Worker 비용, 2D 보기의 프레임 비용(전환 시간만 측정), 라벨 24개 선택 상태.
